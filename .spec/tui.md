# TUI 规范

## 入口与默认状态

主程序通过 `python -m rotations.main` 启动；当前阶段只加载应用配置、检测游戏和展示第一行通用数据，不读取 rotation，也不生成插件。

程序启动后默认暂停：截图、解码与数据展示都由综合页的“启动”按钮开始，“关闭”按钮只停止采集并保留界面，Ctrl+Q 退出程序。

## 应用配置

应用配置是启动工作目录（`Path.cwd()`）下的 `phantom.toml`，与程序目录、源码目录和 rotation 文件位置无关，程序不改变工作目录。rotation 配置的 schema 见 [configuration.md](configuration.md)，两者是不同的文件。

- 目录内没有该文件时写入默认内容；已有文件只读取一次，不重写、不补写缺失字段，也不在运行期间重新加载。
- 缺失字段使用默认值；语法、类型、读写错误在进入界面前明确报告并以非零状态退出，不静默回退。

| 字段 | 默认值 | 约束 |
| --- | --- | --- |
| `capture.fps` | `15` | 有限正数，用作截图与界面读取最新快照的频率上限 |
| `ui.min_width` | `120` | 正整数，界面最小宽度（列） |
| `ui.min_height` | `46` | 正整数，界面最小高度（行） |
| `ui.log_max_lines` | `1000` | 正整数，业务日志保留的最大物理行数 |

## 视觉

界面使用用户提供的 Catppuccin Latte 配色，色值以 [`.context/catppuccin-latte.md`](../.context/catppuccin-latte.md) 为准，不得改写、近似或替换。

- 背景使用 Base，容器使用 Mantle，正文使用 Text，选中与强调使用 Blue。
- 状态“开”使用 Green，状态“关”使用 Peach。

## 布局

- content 填满 footer 之外的剩余空间，footer 贴底、高度由内容决定，并且只包含一行 `status_line`。
- `status_line` 左对齐，各项之间使用 ` · ` 分隔。
- 终端尺寸小于配置的最小值时，content 显示当前尺寸与要求的尺寸，footer 保持可见；恢复尺寸后回到原来的标签页与运行状态。

## 页面与操作

标签页顺序固定为：综合、通用条件、日志、宏绑定、循环条件；默认显示综合。

| 按键 | 行为 |
| --- | --- |
| Tab / Shift+Tab | 在标签页之间循环切换 |
| ↑ / ↓ | 在可用按钮之间移动选择 |
| Enter / Space | 激活当前按钮 |
| Ctrl+Q | 退出程序 |

鼠标操作同样可用。宏绑定页、循环条件页和综合页的“生成插件”按钮保留为占位：按钮禁用并说明尚未实现，不隐藏未来入口。

## 综合页

页面分为约 1:3 的左右两栏：

- 左栏“操作”：启动、关闭、生成插件，以及键位说明。
- 右栏“当前工作状态”：程序状态、游戏状态、采集状态、画布宽高、配置 FPS 和当前问题。

## 通用条件页

表格固定五行，对应第一行已有的五个通用 Cell，顺序为玩家职业、玩家专精、Lua 启动状态、爆发开关、延迟开关。五个值必须来自同一次有效截图的 `getCell(1..5, 1)`。

| 列 | 内容 |
| --- | --- |
| 项目 | 通用字段名称 |
| RGB | Cell 的 `color_string` |
| 亮度值 | 仅当 `is_pure` 为真时显示 `mean`；非纯色显示 `—` |
| 显示值 | 当前阶段固定为空 |

暂停、截图失败或解析失败都清空已有原始值，不保留过期数据；恢复后由新的有效帧重新填充。

## 日志页

业务日志是与 Textual、Python 诊断日志分离的独立通道，只通过 `log(message: str)` 写入，不写入每帧数据。

- 写入时添加本地 `[HH:MM:SS]` 时间戳，并在加时间戳之前丢弃与上一条完全相同的正文。
- 最多保留 `ui.log_max_lines` 行物理行，超出时淘汰最旧的行；日志填满页面空间并可滚动。
- 记录程序启停、游戏状态变化、采集失败与恢复，以及停止失败等业务事件。

## 游戏检测

游戏状态由后台线程每秒独立检测一次，判定为：进程名大小写不敏感等于 `wow.exe`，且可执行文件的直接父目录为 `_retail_`。不绑定盘符、安装路径或进程数量。

- 没有任何确认匹配的进程时禁用“启动”。
- 无法读取可执行文件路径的候选进程不能算作游戏正在运行，并在界面说明原因。
- 游戏退出时停止采集并清空数据；游戏重新启动后不自动恢复采集，需要再次手动启动。

## 采集生命周期

采集复用 `phantom/captures/` 已有的 GDI worker 与最新结果快照：按配置 FPS 读取最新快照并解码，不排队历史帧。进程查询和阻塞停止都不在 UI 线程执行，界面通过 Textual 消息更新。

- 截图 worker 提供只读运行状态，用于区分可恢复的定位、校验错误与线程已结束。
- 线程致命结束时暂停程序、显示失败原因，并允许用户显式重新启动。
- 关闭按钮、游戏退出和应用退出共用同一套清理流程：停止期间禁用启动、等待资源释放、拒绝暂停后到达的过期结果；进程退出前等待后台线程结束。
